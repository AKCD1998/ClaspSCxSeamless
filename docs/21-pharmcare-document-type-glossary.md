# 21 PharmCare Document Type Glossary

วันที่จด: 2026-08-19
สถานะ: อ้างอิง (ไม่ใช่ living doc — อัปเดตเมื่อความเข้าใจเปลี่ยนหรือยืนยันความหมายจาก PharmCare ได้ชัดขึ้น)

## จุดประสงค์

อธิบายว่าตัวเลือก "ประเภทเอกสาร" แต่ละอันในตัวกรองของหน้า PharmCare Inbox
(`DOCUMENT_TYPE_LABELS` ใน `client/src/components/pharmcareLabels.js`) หมายความว่าอะไรจริงๆ
— จดไว้เพราะป้ายชื่อปัจจุบัน (เช่น "Settlement (MRR)", "Settlement (SFR)") เป็นศัพท์เทคนิคที่
ทีมพัฒนาตั้งตามชื่อไฟล์ที่ PharmCare ส่งมา **ไม่ใช่ศัพท์ที่คนในบริษัทใช้เรียกกันจริงๆ**
เมื่อไหร่ที่จะ simplify UI ให้คนที่ไม่ใช่สายเทคนิคเข้าใจได้ทันที ให้เริ่มจากไฟล์นี้

อ้างอิงหลัก: `docs/13-pharmcare-finance-email-automation.md` (ตารางจำแนกประเภทจริง,
บรรทัด 81-86 และ 182-188)

## ตารางความหมาย

| ป้ายใน dropdown | ชื่อภายในระบบ | ความหมาย | สัญญาณที่ระบบใช้จำแนก | หมายเหตุ |
|---|---|---|---|---|
| **ทั้งหมด** | — | ไม่กรอง แสดงทุกประเภท | — | ค่าเริ่มต้น |
| **E-Credit Invoice** | `e_credit_invoice` | ใบแจ้งหนี้/ใบกำกับภาษีอิเล็กทรอนิกส์รายเคส — เอกสารการเงินที่พบบ่อยที่สุด (39/56 ฉบับในตัวอย่างที่สำรวจ) แต่ละฉบับผูกกับเคสหนึ่งเคส มีเลขที่เอกสารขึ้นต้นด้วย `CIV` | หัวเรื่องมีคำว่า "PharmCare e-credit invoice" และไฟล์แนบชื่อขึ้นต้นด้วย `CIV` | หนึ่งเคสอาจมี CIV มากกว่าหนึ่งฉบับได้ (ยังไม่ยืนยัน 100% — ดู open question ด้านล่าง) |
| **Settlement (MRR)** | `settlement_mrr` | รายงานสรุปยอดเงินประจำรอบ (ทุก 15 วัน) — "MRR" คาดว่าย่อมาจาก **Medicine/Reimbursement Report** (ยังไม่ได้ยืนยันจาก PharmCare อย่างเป็นทางการ) | หัวเรื่องมีคำว่า "รายงานสรุปข้อมูลบริการ" และไฟล์แนบชื่อขึ้นต้นด้วย `MRR` | มาคู่กับ SFR เสมอในอีเมลเดียวกัน — ถ้าเจอ MRR แต่ไม่เจอ SFR ของรอบเดียวกัน แปลว่ารอบยังไม่ครบ |
| **Settlement (SFR)** | `settlement_sfr` | รายงานสรุปยอดเงินประจำรอบ (ทุก 15 วัน) เช่นกัน — "SFR" คาดว่าย่อมาจาก **Service Fee Report** (ยังไม่ได้ยืนยันจาก PharmCare อย่างเป็นทางการ) | หัวเรื่องมีคำว่า "รายงานสรุปข้อมูลบริการ" และไฟล์แนบชื่อขึ้นต้นด้วย `SFR` | คู่กับ MRR เหมือนกัน — ทั้งคู่รวมกันเรียกว่า "settlement cycle" ในระบบ |
| **ใบเสร็จ/ใบกำกับภาษี (รอลิงก์)** | `receipt_link_pending` | อีเมลแจ้งว่ามีใบเสร็จรับเงิน/ใบกำกับภาษีให้ไปเปิดผ่านลิงก์ของ PharmCare เอง — **อีเมลนี้ไม่มีไฟล์แนบมาด้วย** ต้องกดลิงก์ไปดาวน์โหลดเองที่ปลายทาง | หัวเรื่อง/เนื้อหาอีเมลกล่าวถึงใบเสร็จ/ใบกำกับภาษี แต่ไม่มีไฟล์แนบ | ระบบยังไม่ได้ไปดึงไฟล์จากลิงก์อัตโนมัติ (งานที่ยังไม่ได้ทำ — ดู docs/13 บรรทัด 84) ต้องมีคนไปเปิดลิงก์เองตอนนี้ |
| **สัญญา** | `contract` | เอกสารสัญญา (เช่น สัญญา Telepharmacy) — ไม่ใช่เอกสารการเงินรายรอบ | หัวเรื่อง/เนื้อหาอีเมลกล่าวถึงคำว่า "สัญญา" | ไม่เข้าชุดพิมพ์บัญชีอัตโนมัติ (excluded by design เพราะไม่ใช่เอกสารบัญชีปกติ) |
| **ไม่ทราบประเภท** | `unknown` | ระบบจำแนกไม่ได้เลยว่าเป็นเอกสารประเภทไหน | ไม่ตรง pattern ใดๆ ข้างต้น | คนละกรณีกับสถานะ "ต้องตรวจสอบ" (`manual_review`) — อันนี้คือ "ไม่รู้จักประเภทเอกสาร" ส่วนอันนั้นคือ "ต้องมีคนมาตรวจสอบก่อนยืนยัน" ทั้งสองอย่างอาจเกิดพร้อมกันได้ |

## ศัพท์ที่ทีมพัฒนาใช้ vs ที่ควรอธิบายให้คนทั่วไปฟัง

แนวทางคร่าวๆ ถ้าจะ simplify ในอนาคต (ยังไม่ได้ทำ แค่จดไอเดียไว้):

- **"E-Credit Invoice"** → อาจเรียกง่ายๆ ว่า "ใบแจ้งหนี้รายเคส"
- **"Settlement (MRR)" / "Settlement (SFR)"** → เป็นชื่อที่งงที่สุดสำหรับคนนอกทีม เพราะ MRR/SFR
  เป็นตัวย่อภายในไฟล์ของ PharmCare เอง ไม่ใช่ศัพท์บัญชีทั่วไป — ถ้าจะ simplify แนะนำรวมสองอันนี้
  แสดงเป็น "รายงานสรุปยอดประจำรอบ (15 วัน)" ในมุมมองผู้ใช้ทั่วไป แล้วเก็บ MRR/SFR แยกไว้เป็น
  รายละเอียดสำหรับ admin เท่านั้น (สอดคล้องกับที่ระบบ role-based ซ่อนคอลัมน์ "สถานะ" ให้ user
  ทั่วไปอยู่แล้ว — ดู `docs/20` task 6)
- **"ใบเสร็จ/ใบกำกับภาษี (รอลิงก์)"** → ชัดเจนอยู่แล้วสำหรับคนทั่วไป แต่ควรเพิ่มคำอธิบายว่า
  "ต้องกดลิงก์ในอีเมลต้นฉบับเพื่อดาวน์โหลดเอง ระบบยังไม่ได้ดึงไฟล์ให้อัตโนมัติ"
- **"ไม่ทราบประเภท"** → ควรมีคำอธิบายเสริมว่า "ระบบจับรูปแบบไม่ได้ ต้องเปิดดูอีเมลจริงเพื่อระบุ
  ประเภทเอง"

## Open questions (ยังไม่ยืนยัน)

จาก `docs/13-pharmcare-finance-email-automation.md` บรรทัด 127-133 และ 309-312:

1. ความหมายเต็มของตัวย่อ MRR/SFR ยังไม่ได้ยืนยันจาก PharmCare อย่างเป็นทางการ (แค่คาดเดาจาก
   บริบท) — ควรยืนยันก่อนตั้งชื่อ field ทางบัญชีอย่างเป็นทางการ หรือก่อนใช้ในเอกสาร simplify
   ที่จะสื่อสารกับคนในบริษัท
2. หนึ่งเคส CIV (e-credit invoice) มีได้มากกว่าหนึ่งฉบับ หรือมีฉบับแก้ไข (revision) ได้หรือไม่
   — ยังไม่ยืนยัน
3. รอบ (cycle) ที่ไม่มีอีเมลเข้ามาเลย หมายถึงไม่มี transaction ในรอบนั้นจริงๆ หรือเป็นเอกสาร
   ตกหล่น — ยังไม่ยืนยัน
